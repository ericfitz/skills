# Plugin renaming and consolidation: design

Date: 2026-11-21. Status: approved decisions recorded; ready for planning.

## Intent

The `estack` marketplace (this repo) uses short, abbreviated plugin names (`loc`, `ui`, `dev`,
`cats`, `itest`, `env`, ...). Eric wants them longer, standardized and descriptive, so that a
plugin's name says what it does, and related plugins read as a group. Every skill is invoked as
`/<plugin>:<skill>`, so the plugin name is what users type and read.

## Goals

- Every `estack` plugin has a descriptive, unabbreviated name following the scheme below.
- Testing plugins share a `test-` prefix; the two discovery plugins become one `discover` plugin.
- `dev` leaves `estack` and lives in `old-skills` (ericfitz/old-skills) as `sem`, with history.
- Every reference to an old plugin name in live files is updated; all four exit checks pass after
  each stage.

## Non-goals

- Skill names do not change, except the two `report` skills that collide in `discover` and
  `itest:design` (decision 7). New shortcut skills are added (decision 8); no other new
  functionality.
- No backward compatibility for old data labels (contract identifiers) or old install names.
- No changes to the four plugins already in `old-skills` (security, wiki, writing, logseq).
- Historical specs and plans under `docs/superpowers/` keep the names they were written with.

## Anti-goals

- Losing any plugin file or history in the `dev` move.
- A stage that leaves `main` (or the branch) with failing checks.
- Changing per-repo config folder paths that other repos already rely on.

## Decisions (human-made, recorded as such)

All of these were decided by Eric in the 2026-11-21 brainstorming conversation.

1. **Naming scheme.** Testing plugins take a `test-` category prefix and stay separate plugins.
   Plugins that do not cluster take single-word nouns. `ui` becomes `test-ui` (Eric's choice over
   `test-visual-regression`).
2. **Final names.**

   | Current | New | Skills |
   |---|---|---|
   | `cats` | `test-api-fuzzing` | init, run, report, analyze, fp, + api-fuzz |
   | `itest` | `test-integration` | integration-test-plan (was design), conventions, critique, state |
   | `ui` | `test-ui` | vrt |
   | `openapi` | `test-api-workflows` | init, arazzo, + api-workflows |
   | `profile` + `dependency-model` | `discover` | see decision 3 |
   | `github` | `issues` | backlog, create-issue |
   | `session` | `session` (unchanged) | go, handoff |
   | `deps` | `dependencies` | bump |
   | `loc` | `localization` | analyze, backfill, coverage, detect-nonloc, translate-to, update-json, validate-translation |
   | `env` | `environment` | check |
   | `dev` | moves to `old-skills` as `sem` | dedupe, sem-annotate, sem-auto |

   `estack` goes from 12 plugins to 10.
3. **`discover` merge.** `profile` and `dependency-model` merge into one plugin, `discover`.
   The colliding `report` skills are renamed:
   - `profile:report` (offline HTML project report) becomes `discover:project-report`.
   - `dependency-model:report` (renders `docs/dependencies.md`) becomes `discover:dependency-report`.
   All other skills keep their names: docs, journeys, stack, topology (from profile); package,
   service, config, security, platform, network, synthesize (from dependency-model).
   With the shortcuts of decision 8, `discover` has 15 skills.
4. **Compatibility.** Per-repo config folders keep their paths: `.local/cats/` and
   `.local/openapi/` are named after the tools and stay as-is (in use by `tmi` and `agentmesh`).
   Data labels switch to the new plugin names outright by text substitution. Nothing validates
   labels today and nothing is added (no `const`), so saved output with old labels still
   validates; it is simply stale and regenerated by rerunning the skill.
5. **Versions.** Renamed plugins keep their current `version`. `contract_version` values do not
   change; only the labels do. `discover` starts at `1.0.0` (profile's version).
6. **Sequencing.** Staged commits on one branch (stages 1-3, plus stage 4 for decisions 7 and 8), each passing all four exit checks, then a local
   merge into `main` and push (this repo never uses PRs).
7. **`itest:design` renamed** to `integration-test-plan` (it produces a prioritized
   integration-test scenario plan; it writes no test code). Full form
   `/test-integration:integration-test-plan`; being descriptive on its own, it doubles as the
   short command `/integration-test-plan`, so it needs no wrapper.
8. **End-to-end shortcut skills.** Thin skills that only chain existing skills, so the user does
   not have to remember which skills to run in which order. No new functionality.

   | Shortcut | Plugin | Chains |
   |---|---|---|
   | `dependency-model` | `discover` | `synthesize` (which runs topology, the six dependency discovery skills and the merge), then `dependency-report` |
   | `project-profile` | `discover` | `stack`, `docs`, `journeys`, `topology`, then `project-report` |
   | `api-fuzz` | `test-api-fuzzing` | `init` only if `.local/cats/config.yaml` is missing, then `run`, `report`, `analyze` |
   | `api-workflows` | `test-api-workflows` | `init` only if the spec is not yet recorded in `.local/openapi/config.yaml`, then `arazzo` |

## Approaches considered

1. **Three staged commits on one branch (chosen).** Stage 1: move `dev`. Stage 2: mechanical
   renames. Stage 3: the `discover` merge. Each stage is reviewable and revertible alone, and
   the one stage that needs judgment (the merge) is isolated.
2. **One big commit.** Less overhead, but a ~200-file diff that mixes mechanical renames with the
   merge; a failing check is hard to localize. Rejected.
3. **Merge first, then rename.** Same end state, but the merge is written against old names and
   then rewritten. Rejected as churn.

Grouping alternatives also considered: merging all testing plugins into one `test` plugin
(rejected by Eric: skill-name collisions such as two `init` skills, a merged tool-requirement
set, all-or-nothing install); plain descriptive names without prefixes; tool-first names.

## Stage 1: move `dev` to `old-skills` as `sem`

Same method used on 2026-11-21 for the other four plugins:

- In a fresh `git clone --no-local` of this repo, `git-filter-repo --path dev` plus any
  dev-only tests (`tests/test_sem_*`, `tests/test_dedupe*`, and fixtures they use; the builder
  identifies the exact set by import and fixture use), then `git-filter-repo
  --path-rename dev/:sem/` and the corresponding test renames if needed.
- Prove nothing was lost before deleting: tree hashes of the moved directory match (`HEAD:dev`
  in skills equals the pre-rename tree), and dev's test count is identical in both repos.
- Pull the filtered history into `/Users/efitz/Projects/old-skills` (for example, add the
  filtered clone as a remote and merge with `--allow-unrelated-histories`), then rename the
  plugin to `sem`: `sem/.claude-plugin/plugin.json` `name`, `old-skills` marketplace entry,
  `PLUGINS` array in its `verify-marketplace.sh` (category `development`), regenerated Codex
  manifests, README section, `pyproject.toml`/`tests/__init__.py` path entries (`sem/scripts`),
  per-file `sys.path.insert` lines in the moved tests, and ruff `known-first-party` entries the
  dev tests need. Agent files under `dev/agents/` move with it; `${CLAUDE_PLUGIN_ROOT}/agents/...`
  references are unchanged, but plugin-namespaced agent names change (e.g.
  `dev/skills/sem-annotate/SKILL.md:87` `dev:SEM Describer` becomes `sem:SEM Describer`).
- Remove `dev` from this repo: directory, its tests, marketplace entry, `PLUGINS` entry, the
  `dev worker agents` section and `dev/scripts/*` lines in `verify-marketplace.sh`,
  `pyproject.toml` / `tests/__init__.py` path entries, `tests/test_env_declarations.py`
  `EXEMPLAR_PLUGINS` (drop `dev`; it changes again in stage 2 for `env`/`github`), README
  section and count, ARCHITECTURE
  node/rows (dev has a dependency edge: `dedupe` reads markers `sem-annotate` writes; that
  edge leaves with it), and the README Architecture paragraph that cites `dev:dedupe`.
- Push `old-skills` (outward action; Eric approves the push).

## Stage 2: mechanical renames

For `cats`, `itest`, `ui`, `openapi`, `github`, `deps`, `loc`, `env` (session is unchanged):

- `git mv <old> <new>`; update `<new>/.claude-plugin/plugin.json` `name`, and `requirements.json`
  `plugin` field.
- Marketplace entry `name` and `source` (`./<new>`); description text unchanged except where it
  names the plugin.
- `verify-marketplace.sh`: `PLUGINS` array (keep the existing category values), `SCRIPTS` paths.
- Regenerate Codex manifests (`uv run scripts/gen_codex_manifests.py`); delete stale
  `<old>/.codex-plugin` (moves with `git mv`).
- Every invocation reference in live files: `/<old>:<skill>` and `<old>:<skill>` become
  `/<new>:<skill>` / `<new>:<skill>` (SKILL.md bodies and descriptions, hooks, scripts,
  README, ARCHITECTURE, CLAUDE.md, tests). Notable: `session` invokes `github:backlog` (becomes
  `issues:backlog`), `itest` invokes `profile:*` (handled in stage 3), `openapi:arazzo` reads
  what `itest:design` writes.
- Contract labels switch to the new plugin name, e.g. `itest:critique` becomes
  `test-integration:critique`. Labels live only in schema `title`s, `seeded_by.contract`
  values in examples, and prose; no schema has a `contract` field or a `const`, and no script
  compares labels.
- Plugin-cache path examples (`~/.claude/plugins/cache/estack/<old>/...`) become `<new>`.
- Script-dir paths for renamed plugins wherever they appear: `pyproject.toml` pytest
  `pythonpath` and ty `extra-paths`, `tests/__init__.py`, per-file `sys.path.insert` lines in
  tests, and `tests/schema_check.py`.
- Test files may keep their file names (`tests/test_cats_*.py`, `tests/test_bump_*.py`); only
  path and label strings inside them change. Python library names (`catslib`, `bumplib`) do not
  change.
- Tool names that coincide with old plugin names are **not** plugin references and must not be
  rewritten: the CATS tool (`cats` binary, `cats_tool.py`, `catslib`, `.local/cats/`), OpenAPI
  as a standard (`.local/openapi/`, "OpenAPI spec"), GitHub as a product, `gh`.
- Outside this repo (Eric decided: update all of them, one small commit per repo, each push
  approved by Eric):
  - `tmi/Makefile:534-535`: the `cats_tool.py` lookup becomes
    `~/.claude/plugins/cache/estack/test-api-fuzzing/*/scripts/` with fallback
    `~/Projects/skills/test-api-fuzzing/scripts/` (the old cache path still names `efitz-skills`).
  - `/cats:*` text references: `tmi/.claude/CLAUDE.md:48`, `tmi/.claude/skills/cats-tmi/SKILL.md:8`,
    `tmi/scripts/README.md:48`, `agentmesh/scripts/cats-precommit.sh:219`.
  - `deps:bump`: `renamer/CLAUDE.md`, `scan-namer/CLAUDE.md`, and the user-level
    `~/.claude/commands/bump.md` (not a repo; edited in place).
  - Before editing each repo, `rg` it once more for every old plugin name, since other sessions
    may have added references.

## Stage 3: merge into `discover`

- Create `discover/` from `profile/` (`git mv profile discover`), then `git mv` each
  `dependency-model/` child into it: `skills/*`, `scripts/*`, `references/*.md`,
  `references/contracts/*` and `references/contracts/examples/*`. No file names collide
  (verified 2026-11-21).
- Rename skill dirs `skills/report` (profile's) to `skills/project-report` and
  dependency-model's `skills/report` to `skills/dependency-report`; update each SKILL.md
  `name:` frontmatter and every invocation (`/profile:report`, `/dependency-model:report`).
- `discover/.claude-plugin/plugin.json`: `name: discover`, `version: 1.0.0`, merged description.
  One marketplace entry (category `development`), one `PLUGINS` entry listing all 13 skills in
  directory-listing order.
- `requirements.json`: union of both. `syft` stays **required**: `/environment:check` checks
  plugins individually and has no plugin-dependency field, so a required `syft` can only fail
  `discover` itself, never `test-integration`; the dependency skills cannot work without it.
- Labels: `profile:<x>` and `dependency-model:<x>` become `discover:<x>` everywhere: schema
  `title`s, `seeded_by.contract` values in examples, and prose in consumers (`itest`/
  `test-integration` skills, `dependency-model` skills seeded by `profile:topology`). This
  yields `discover:discovery` and `discover:synthesis` for dependency-model's envelope
  contracts.
- Script paths `dependency-model/scripts` and `profile/scripts` become `discover/scripts`
  wherever they appear: ty `extra-paths` in `pyproject.toml`, per-file `sys.path.insert` lines
  in about 35 test files, and `tests/schema_check.py`. ruff `known-first-party` entries are
  unchanged (module names do not change).
- Contracts stay in one flat `discover/references/contracts/` (with `examples/`). The two
  directory-wide test guards are rewritten to explicit per-origin schema lists:
  `tests/test_profile_contracts.py:48-66` (every schema carries `contract_version` and a
  validating same-named example) applies to the profile-origin schemas, and
  `tests/test_dependency_model_contracts.py:280-294` (no `criticality`/`reachable`) applies
  to the dependency-origin schemas. A new test fails on any schema in the directory that is in
  neither list, so new schemas are never silently unguarded.
- `profile_report.py`'s default output `profile-report.html` becomes `project-report.html`
  (user-visible; matches the skill name). The temp run dir `dependency-model-<key>`
  (`depscanlib/run.py:94`) keeps its name.
- ARCHITECTURE.md: merge the two nodes into one `discover` node in the Mermaid graph, update
  edges (`test-integration` → `discover`), the skill catalog, and entry-point table; re-render
  the graph with `npx -y -p @mermaid-js/mermaid-cli mmdc -i <extracted.mmd> -o /tmp/out.svg` to
  confirm it parses.
- README: one `### discover` section combining both, with the two renamed reports.

## Stage 4: shortcut skills

- Rename `itest`'s `skills/design` to `skills/integration-test-plan` (do this in stage 2 with the
  plugin rename) and update every `/itest:design` / `itest:design` reference.
- Add the four shortcut skills of decision 8 as `<plugin>/skills/<name>/SKILL.md`. Each one:
  invokes the chained skills **by name** in order (never by script path), passes through the
  same arguments (`[path]`, `--ref`, etc.) where the chained skills accept them, honors each
  chained skill's own confirmation gates, and stops on the first failure, reporting which step
  failed. Frontmatter sets `disable-model-invocation: true`, so the shortcut is for the user to
  type and does not compete with the skills it wraps for automatic invocation.
- Bare invocation (`/dependency-model`) is documented as working when no other command uses the
  name (https://code.claude.com/docs/en/skills.md); verify it in a real session after install. If
  a bare name is taken, the namespaced form still works; report it rather than renaming.
- Each shortcut is added to the `PLUGINS` skill list, README, ARCHITECTURE entry-point table and
  Codex manifests (regenerated). Codex has no bare-slash form; the README lists the namespaced
  name for Codex.
- Tests: a structural test that each shortcut's SKILL.md names only skills that exist in its own
  plugin, and has `disable-model-invocation: true`.

## Constraints

- Exit criteria after each stage: `uv run ruff check .`, `uv run pytest -q`,
  `uv run scripts/gen_codex_manifests.py --check`, `bash scripts/verify-marketplace.sh`.
  Same four in `old-skills` for stage 1.
- After all stages, `rg` for each old plugin name followed by `:` or `/` in live files (excluding
  `docs/superpowers/`, tool-name exceptions above) returns nothing.
- No plugin or contract version changes beyond decision 5.
- Pushes (this repo's `main`, `old-skills`, `renamer`, `scan-namer`) are outward actions.

## Calls made by the author (Claude), not Eric

- Category values in `marketplace.json` stay as they are today (e.g. `cats` stays `testing`,
  `itest` stays `development`); the `test-` prefix is in the name, not the category.
- `syft` stays required in `discover`'s requirements (see stage 3).
- Flat contracts directory with per-origin guard lists plus an unknown-schema test (see stage 3).
- `profile-report.html` default output renamed `project-report.html`; temp dir name kept.
- Test file names keep their old prefixes; only contents change.
- Stage 1 merges history into the existing `old-skills` repo rather than replacing it.
- Shortcuts set `disable-model-invocation: true` and stop on the first failed step.
